# Robinhood Chain beta runbook

## Local verification before touching the network

Node 24: `npm ci && npm run build && npm test && npm run simulate && npm run contracts:compile`. Run `npm start` and inspect `http://localhost:3000/healthz` and the island. A wallet is optional for free play. Local contract tests deploy mock tokens and the real OutpostStore bytecode to a Ganache EVM at chain ID 46630; they test signed orders, 80/20 retirement, asset gating, match unlock, replay protection, pause, and receipt fulfilment. These tests do not deploy anything to Robinhood testnet.

## Robinhood testnet 46630

1. Copy `.env.example` to `.env`. Set `CHAIN_ID=46630`, `VITE_CHAIN_ID=46630`, `APP_ORIGIN` to the actual HTTPS beta host, and `RPC_URL` to a reliable Robinhood testnet RPC. Set `VITE_WALLETCONNECT_PROJECT_ID` to your own public WalletConnect Cloud project ID for RainbowKit's QR/mobile options. Installed EVM wallets can connect without it. Never put a private key in a `VITE_*` variable. WalletConnect origin/domain configuration must include the beta host.
2. Supply `OWNER_ADDRESS` (prefer a test multisig), `TREASURY_ADDRESS`, and `QUOTE_SIGNER_ADDRESS`. Keep separate `DEPLOYER_PRIVATE_KEY` and `QUOTE_SIGNER_PRIVATE_KEY` only in the developer environment. Get test ETH for gas. Run `npm run contracts:deploy -- --testnet-mocks` and inspect the dry run. Then run `npm run contracts:deploy -- --testnet-mocks --broadcast`. Record all deployment addresses and explorer transaction links. The command does **not** broadcast without `--broadcast`.
3. Set `STORE_ADDRESS`, `TOKEN_ADDRESS`, `STABLE_ADDRESS`, signer secret, and a test tariff such as `TOKEN_UNITS_PER_DOLLAR=10`. Keep `TOKEN_DECIMALS=18`, `STABLE_DECIMALS=6`. Run `npm run preflight`. Check the printed token/signer/treasury addresses against the deployment receipt.
4. For each QA address set `BETA_WALLET_ADDRESS`; inspect `npm run beta:fund`, then run `npm run beta:fund -- --broadcast`. This transfers mock assets from the deployer. Test assets are not canonical RIVAL or real USDG. QA wallets separately need test ETH for gas.
5. Build with the **same** client chain/WalletConnect variables as the API, start the app, and use an incognito browser. Test RainbowKit QR on mobile and an installed wallet on desktop. Connect, switch to 46630, sign the domain-bound account-link challenge, create a captain, refresh and restore that account.
6. Play three tactical matches. Check that the RIVAL-only captain edition is locked before three and unlocked after; a USDG quote for a RIVAL-only edition must fail. Inspect the quote, approve the exact test-token amount, buy an edition **with a fresh price check**, and check `Purchased` on the explorer, dead-address 20%, treasury 80%, inventory and equipped battlefield appearance. Buy a normal USDG cosmetic; that checkout routes 100% to treasury without a RIVAL price proof. Request two quotes for the **same** SKU in separate tabs: after one lands, the second purchase must revert before payment. Retry a pending receipt and check double fulfilment is rejected. Let a short RIVAL quote expire during approval; the UI must request and display a new price before purchase. Change the test tariff by more than 3% before requesting the price check; the old order must be rejected at the API and at the contract with a signed moved-price proof. Verify a missing/expired proof fails even when the old order signature remains valid.
7. Switch wallet/account and network; a stale quote must clear and a different wallet must link its own captain. Pause the store to verify checkout fails; unpause for continued QA. Compare the Economy screen confirmed totals to onchain receipts. Test mobile sizing, reduced motion, refresh, two-browser room and server restart.

The build requires the **v1.4 OutpostStore bytecode** exposing `priceGuardVersion() = 1` and `purchasedSku`. The EIP-712 order domain is version 2; the preflight fails against an older store. A one-time database migration backfills confirmed purchase totals; back up the existing SQLite database before upgrading.

`/healthz` confirms server liveness and `/readyz` confirms database availability. Neither proves wallet, RPC, pricing or payment readiness. Save public testnet explorer links and the QA findings before any mainnet decision.

## Mainnet boundary

o1 `launch:prepare` creates an **unsigned** plan, not a token or pool. The testnet MockToken must never be used on mainnet. Mainnet RIVAL checkout also requires the canonical o1 token address, real verified USDG address, a separately operated live bounded feed, o1 read key, indexed pool price/liquidity validation and an actual wallet timing test. An indexed $50k liquidity estimate is a gate, not guaranteed exit liquidity. Do not enable RIVAL checkout during the thin opening market. Contract/security review, real purchase smoke test, persistent storage, backups and support/incident ownership are needed before paid release. The isometric island remains a local visual simulation, and new editions are one-time cosmetics; no creator marketplace, automatic treasury buyback or guaranteed token appreciation exists here.
